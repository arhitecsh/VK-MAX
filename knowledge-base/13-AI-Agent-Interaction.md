# Руководство по взаимодействию с ИИ-агентами

Этот документ предоставляет рекомендации для ИИ-агентов при взаимодействии с проектом VK-MAX. Он описывает, как получать доступ к базе знаний проекта и интерпретировать ее, а также как работать с кодовой базой.

## Доступ к базе знаний

База знаний проекта организована в виде файлов Markdown (`.md`) в директории `knowledge-base/`. Эти файлы пронумерованы последовательно (например, `00-Overview.md`, `01-Problem.md`, `07-Architecture.md`) для предоставления структурированного обзора различных аспектов проекта. ИИ-агенты могут напрямую парсить эти файлы для получения информации.

Как указано в `README.md` проекта, "ИИ — скрытая технология, а не чат." Это подразумевает, что ИИ следует использовать как инструмент для анализа, извлечения информации и понимания кода, а не как собеседника в основной функциональности проекта.

## Понимание структуры проекта для ИИ

Проект построен с использованием React 18, TypeScript и Vite. Исходный код организован следующим образом:

*   **`src/components/`**: Переиспользуемые UI-компоненты.
*   **`src/pages/`**: Экраны или представления приложения.
*   **`src/data/`**: Mock-данные, используемые для разработки. Это ключевая область для анализа ИИ текущих структур данных.
*   **`src/context/`**: Глобальное управление состоянием с использованием React Context и `useState`. Этот файл (`AppContext.tsx`) также содержит основные действия для манипулирования данными.
*   **`src/lib/`**: Вспомогательные функции.
*   **`src/types/`**: TypeScript-интерфейсы, определяющие структуры данных.

Архитектура подчеркивает четкое разделение ответственности. Используются mock-данные, и структура предназначена для будущей интеграции с реальным API бэкенда. Эта изоляция означает, что ИИ-агенты могут анализировать текущие структуры данных и понимать, как они будут сопоставлены с реальными ответами API.

## Ключевая информация для ИИ-агентов

*   **Источник данных:** В настоящее время все данные являются mock-данными, расположенными в `src/data/`. Проект спроектирован для облегчения будущей замены на реальный API.
*   **Управление состоянием:** Основное управление состоянием осуществляется через `React Context` и `useState` в `src/context/AppContext.tsx`.
*   **Основная логика:** Логика приложения в основном управляется в директории `src/context/` и UI-компонентах в `src/components/` и `src/pages/`.
*   **Архитектура:** Проект следует модульному дизайну, отдавая приоритет простоте будущей интеграции с бэкендом.

## Пример взаимодействия (концептуальный)

*   **Анализ пользовательских сценариев:** ИИ-агенту может быть поручено понять пользовательские пути. Он прочитает `knowledge-base/04-User-Flows.md`, а затем, возможно, изучит директории `src/pages/` и `src/components/`, чтобы сопоставить документацию с деталями реализации.
*   **Идентификация структур данных:** Если ИИ-агенту будет предложено определить потенциальные точки данных для новой функции, он может проанализировать типы, определенные в `src/types/`, и mock-данные в `src/data/`, чтобы понять существующие схемы данных.

Используя эту структурированную документацию и кодовую базу, ИИ-агенты могут эффективно способствовать пониманию, анализу и потенциальному расширению проекта VK-MAX.
