# Руководство по контрибьюции в VK-MAX

Добро пожаловать в проект VK-MAX! Мы рады вашему участию. Это руководство описывает процесс внесения вклада в данный репозиторий.

## Кодекс поведения

Пожалуйста, обратите внимание, что этот проект придерживается Кодекса поведения. Участвуя, вы обязуетесь его соблюдать.

## Начало работы

Чтобы начать разработку, выполните следующие шаги:

1.  **Сделайте форк репозитория:** Создайте форк этого репозитория в вашей учетной записи GitHub.
2.  **Клонируйте ваш форк:** Клонируйте ваш форк на локальную машину:
    ```bash
    git clone https://github.com/YOUR_USERNAME/VK-MAX.git
    cd VK-MAX
    ```
    Замените `YOUR_USERNAME` на ваше имя пользователя GitHub.
3.  **Установите зависимости:** Установите зависимости проекта, используя ваш предпочтительный менеджер пакетов:
    ```bash
    # Используя npm
    npm install

    # Или используя pnpm
    pnpm install
    ```
4.  **Запустите сервер разработки:** Запустите приложение локально, чтобы увидеть ваши изменения:
    ```bash
    # Используя npm
    npm run dev

    # Или используя pnpm
    pnpm dev
    ```
    Это обычно запускает сервер разработки, часто по адресу `http://localhost:5173` (по умолчанию Vite).

## Внесение изменений

Мы рекомендуем работать над отдельной веткой для каждой новой функции или исправления ошибки.

1.  **Создайте новую ветку:**
    ```bash
    git checkout -b feature/your-feature-name
    # или
    git checkout -b fix/your-bug-fix
    ```
2.  **Напишите код:**
    *   Следуйте существующему стилю кодирования, который использует React 18 с TypeScript и CSS Modules.
    *   Убедитесь, что ваш код хорошо прокомментирован там, где это необходимо.
    *   Если вы добавляете или изменяете данные, убедитесь, что они соответствуют типам, определенным в `src/types/`, и структуре mock-данных в `src/data/`.
    *   Проект в настоящее время использует mock-данные и имеет изолированную архитектуру, предназначенную для будущей интеграции с API. Пожалуйста, поддерживайте это разделение.
3.  **Зафиксируйте ваши изменения:**
    *   Используйте четкие и описательные сообщения коммитов. Распространенный шаблон: `feat: добавить новую функцию` или `fix: исправить ошибку`.

## Отправка изменений

1.  **Отправьте вашу ветку:**
    ```bash
    git push origin feature/your-feature-name
    ```
2.  **Откройте Pull Request:** Перейдите в исходный репозиторий на GitHub и откройте Pull Request из вашей ветки.
3.  **Опишите ваши изменения:** Предоставьте четкое и краткое описание внесенных изменений, включая решаемую проблему и способ тестирования.

## Сообщение об ошибках

Если вы столкнулись с ошибками или у вас есть предложения по новым функциям, пожалуйста, откройте issue в трекере GitHub для этого репозитория. Предоставьте как можно больше деталей, включая шаги для воспроизведения проблемы.

Спасибо за ваш вклад!
